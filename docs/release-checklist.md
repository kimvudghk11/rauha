- 팀원의 셸 명령 검사는 글자 모양 검사라서, 스크립트를 만들어 돌리거나 변수·`python -c` 같은 해석기로 조립하는 명령까지는 막지 못해요(구조적 한계). 비밀 파일이 있는 저장소에서는 디코딩·`eval` 모양만 막아요.
- 이 점검은 실제 창을 띄워 보지 않았어요(코드와 단위 테스트만). 실제 Claude 호출도 하지 않았어요.

## 맥에서 확인 못 한 것

이 PC에는 맥이 없어서 **실제 맥북에서 실행해 보지 못했어요.** 맥은 GitHub Actions(macos-latest) 결과만 근거예요.

- 설치 파일(dmg)을 실제 맥북에서 열었을 때 "Apple은 rauha에 … 악성 코드가 없음을 확인할 수 없습니다" 경고가 뜨는 것은 **확인됨**(2026-11-08, 사용자 맥). macOS 15 이후에는 "우클릭 → 열기"가 통하지 않아서 안내를 `xattr -dr com.apple.quarantine /Applications/rauha.app` 한 줄 또는 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기"로 고쳤어요. 이 방법으로 앱이 열린 뒤의 동작은 확인 못 함.
- 로그인 셸에서 PATH를 읽어 `git`·`aws`·`gh`·`node`·`claude`를 찾는지(Finder로 연 앱): 확인 못 함(순수 함수 부분만 테스트).
- Claude Code 실행 파일(`claude`)이 설치본의 asar 밖에서 실행되는지, 맥 칩(arm64·x64)별로 맞는 것이 들어갔는지: 확인 못 함.
- 맥 창 모양(제목 막대 숨김·신호등 위치), Cmd 단축키, Dock 아이콘, 알림 허용 안내: 확인 못 함(코드와 단위 테스트만).
- 맥에서의 터미널 rauha 찾기(`~/.local/bin`·`/usr/local/bin`·`/opt/homebrew/bin`): 임시 폴더 테스트만, 확인 못 함.
- 문서·데스크톱 폴더 첫 접근 때 맥이 묻는 권한 창: 확인 못 함.
- 브라우저 연동(`ELECTRON_RUN_AS_NODE`로 띄우는 MCP)은 설치본에서 확인 못 함(Windows 개발 실행에서도 실제로 타 보지 않았어요).
- 실제 맥에서의 Claude 로그인(키체인)과 실제 일 맡기기: 확인 못 함.

Windows는 개발 PC에서 개발 실행으로 화면·허락 카드(가짜 팀)·레포·설정·규칙을 직접 확인했어요. Windows 설치 파일(.exe)을 실제로 설치해 실행한 것은 확인 못 함.

## 서명·공증을 켜려면 필요한 것 (맥)

첫 설치 때 뜨는 "확인할 수 없는 앱" 경고(Gatekeeper)는 코드로 없앨 수 없어요. Apple Developer ID 서명과 공증이 필요하고, 가입 여부는 사용자 결정이에요. 서버 빌드는 준비돼 있어서 아래를 갖추면 켜져요.

1. Apple Developer Program 가입(유료, 연 단위). 개인 계정이면 팀 ID가 하나 있어요.
2. "Developer ID Application" 인증서를 만들어 `.p12`로 내보내고 base64로 바꿔요(`base64 -i cert.p12`).
3. appleid.apple.com에서 앱 암호(app-specific password)를 만들어요.
4. GitHub 저장소 Settings → Secrets and variables → Actions에 다섯 비밀을 이름 그대로 등록해요.
   - `CSC_LINK`: 인증서 `.p12`(base64 글 또는 https 주소)
   - `CSC_KEY_PASSWORD`: `.p12` 암호
   - `APPLE_ID`: Apple ID 이메일
   - `APPLE_APP_SPECIFIC_PASSWORD`: 앱 암호
   - `APPLE_TEAM_ID`: 팀 ID(10자리)
5. 다섯 개가 **모두** 있을 때만 `scripts/dist.mjs`가 서명·공증 설정(`hardenedRuntime`, `notarize`)으로 빌드해요. 하나라도 없으면 지금처럼 ad-hoc이라 서버가 깨지지 않아요. 값은 저장소에 쓰지 않아요.

확인 못 한 것: 실제 인증서로 한 번도 돌려 보지 못했어요. 공증은 앱 안의 실행 파일(`app.asar.unpacked`의 Claude SDK 실행 파일, 브라우저 연동)도 모두 서명돼 있어야 통과하는데, 그것이 자동 서명되는지는 첫 실행 때 확인해야 해요. 실패하면 서버 로그의 notarytool 메시지를 보고 맞춰요.
